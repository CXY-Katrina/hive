## Hive 与任务代码的边界

按用户最新要求，Hive 只实现通用资源管理、任务编排、调度、执行、状态/日志/产物归档和展示。部署、安装、服务启动、健康检查、精度测试、性能测试、结果判定及业务清理全部使用外部脚本或所选 vllm-ascend PR 中的代码，不放入 Hive 代码仓，不在 Hive 中复制或改写。

| Hive 保存和执行 | 业务仓库/外部脚本负责 |
|---|---|
| PR、固定 SHA、文件路径、参数、内容摘要 | 具体部署和依赖安装命令 |
| job、节点/容器绑定、依赖、重试/取消策略 | 服务启动与就绪检查 |
| SSH/Docker 执行、精确进程跟踪、超时和资源释放 | 模型下载、权重选择、精度/性能测试 |
| 退出码、结构化结果及原始文件归档 | 结果计算、阈值比较与业务成功/失败判定 |
| 通用标签筛选、结果展示 | 用例枚举和模型/量化/数据集等标签导出 |

Hive 可以保留通用 runner/control 和协议校验代码；其中不出现模型名、pip 安装配方、aisbench 命令或测试通过阈值。资源清理是平台职责，业务服务的收尾逻辑由 PR 脚本提供，两者分别记录完成状态。

任务定义保存在数据库中，引用 PR 文件而不是 Hive 中的模板脚本。准备工作区时按固定 SHA 检出业务代码；运行快照和上传附件属于运行数据，不提交进 Hive Git 仓库。执行代码的新增或变更走 PR。缺少安装入口、标签导出或结果适配时，应在业务 PR 中补充，Hive 明确报告缺失，不补写业务实现。

## 模块和资源归属

| 对象 | 职责 |
|---|---|
| 资源申请 | 复用 ResourceService，拥有实际节点和卡；资源交付前可以排队 |
| 运行空间 | 持有一条任务用途的申请及节点代称绑定，管理其下多个环境和任务的资源生命周期 |
| 环境 | 属于运行空间，独立保存角色、节点绑定、容器身份、依赖配置、安装结果及运行占用 |
| 任务 | 引用运行空间中的一个或多个环境，拥有固定代码配置和一组 job；环境可由多个任务复用 |
| job | 指定节点与容器代称、卡子集、脚本、依赖、检查和超时；自身不释放申请 |
| 远端 attempt | 记录一次启动、身份、退出和日志；容器内运行，负责精确停止自身进程 |
| 预置 | 保存 PR 中清单/YAML/脚本的引用、标签快照和验证状态，实例化成普通任务；不内置业务实现 |

运行空间把申请和多个环境关联起来，避免 server/client 每建一个环境就重复申请同一机器。环境独立于单个任务，不能直接沿用当前 executions.request_id UNIQUE 的一任务一申请关系来表示多个任务共享环境。新运行空间、环境与工作流使用独立持久记录，底层复用资源分配和远端执行原语。既有单脚本执行路径保留兼容。

首次提交可以原子创建申请、运行空间、多个环境和任务；重试相同幂等键返回同一结果，不重复申请。后续任务可选择本人仍有效的运行空间。当前复用要求 PR/vLLM SHA 与已保存安装配置一致，并持续检查资源绑定、节点 boot ID 和容器身份。任务 YAML 的内容摘要独立记录，替换 YAML 不触发重复安装；改变代码 SHA 或安装输入时需要新建运行空间。当前不支持在既有空间中单独替换客户端或服务端环境。

任务运行和安装期间使用任务租约，不应用调试资源的“10 分钟 AI Core 全零”回收规则。默认运行空间中最后一个任务结束后关闭其全部环境并归还资源；选择“保留环境用于后续任务”时继续占用资源、显示空闲保留状态，并可显式关闭。保留不能无限隐蔽占用：界面展示保留截止时间，到期且无运行任务时进入关闭；后续提交可以在有效期内复用。页面勾选保留时默认 60 分钟，可调整，最长 7 天。

关闭运行空间先阻止新任务，再结束所属 attempt、逐环境核验容器内进程退出，最后统一归还资源。当前关闭操作作用于整个空间，不提供单个环境关闭接口。身份失配或关闭结果未知时保留卡锁并提示人工处理。取消一个任务只取消其 job，不破坏同环境其他任务。

## 服务端、客户端与机器关系

机器、环境和角色分别建模。node0、node1 表示申请的机器位置；server_env、client_env 表示独立的容器环境；server、client 是用于说明职责的角色，不决定物理位置。一个角色可以有多个实例，job 显式选择目标环境，节点由环境的绑定确定，避免同时填写互相矛盾的节点和容器。

| 部署方式 | 服务端 | 客户端 | 申请机器数 |
|---|---|---|---:|
| 同机部署 | node0 / server_env / 独立容器 | node0 / client_env / 独立容器 | 1 |
| 分机部署 | node0 / server_env / 独立容器 | node1 / client_env / 独立容器 | 2 |

每个环境在页面配置服务器/容器代称、角色、镜像及安装/核验入口；解释器和软件依赖由脚本管理，旧 API 配置保留兼容。客户端可以只安装测试所需工具，也可以需要自己的 PyTorch/CANN 等依赖，不继承服务端安装清单。同机默认使用两个容器，因此不同依赖版本可以并存；共用机器不代表共用 Python 环境或重复安装同一份环境。

申请数量按唯一节点代称计算，不能按环境个数计算。同机两个环境共享一次节点申请，卡仍按运行 job 的实际声明登记：服务端按需占 NPU，纯请求客户端可以声明零 NPU；客户端若也做 NPU 计算则分配独立卡集合或等待冲突解除。零 NPU 不表示零 CPU、内存或磁盘消耗，按节点限制并发，避免客户端挤占服务端。整机独占/部分卡申请的边界保持由资源申请决定，零卡客户端不改变整机独占范围。

安装状态、日志和复用锁逐环境保存；环境之间无依赖且节点容量允许时可以并行准备。同一环境安装完成前不运行其业务 job，且已有任务使用时不能原地更换依赖。共享盘只用于显式共享的权重/数据/产物路径，各环境的代码、虚拟环境及任务输出使用独立目录，避免同机或共享挂载下相互覆盖。

服务端 job 启动后，由外部就绪检查入口报告 READY，依赖该服务的客户端才开始；不等待长期运行的服务端进程退出。服务 READY 后仍保持其卡和端口占用，客户端无卡 job 可以并行运行。就绪超时、服务提前退出或客户端失败分别记录原因，并按任务收尾策略运行外部清理入口。清理只结束本任务拥有的服务；复用安装环境不自动表示复用另一任务的业务服务。

地址使用服务代称引用，例如 client job 引用 server 的 endpoint。Hive 分配节点后生成实际地址和端口，通过通用上下文传给 PR 入口，不让任务提前填写 IP。当前启动脚本使用 host 网络，端口由用户脚本选择，同机不同容器不能占用同一监听端口；跨机连接由外部前校验确认实际可达，连接失败时不启动依赖测试。

## 代码和环境配置

只接受 vllm-project/vllm-ascend 的 PR 编号或严格匹配该仓库的 PR URL。提交时冻结 PR head SHA；从同一 SHA 的 .github/vllm-main-verified.commit 读取匹配 vLLM SHA。版本文件缺失或内容不能唯一解析时明确报错，不回退到移动中的 main。

调研时上游 main 为 `7a9c1c347a2a2665080b0dc7813e3c8f943586a8`，该文件内容为 `a97dacb7106ee49f39f3d1fc6ae1800ff724e01d`。这是来源调查快照，不代替用户选择的 PR。

每个容器别名有 server 或 client 角色，可配置镜像、PyTorch、torch-npu、CANN、Triton、triton-ascend 和客户端工具。版本与安装来源分开存储，之后可增加带架构、下载地址和校验摘要的软件包目录。这些是传给外部安装脚本的输入；Hive 不根据包名拼接安装命令。没有来源或安装入口的版本不能显示为可自动安装。

首版调用外部脚本基于已有镜像创建新容器，再由 PR 中的检查/安装脚本读取、核验和准备依赖；相同版本无需重装，不同版本且尚无安装来源时阻止执行并给出缺项。vLLM/vLLM-Ascend 的构建和安装由外部入口在任务隔离目录中按固定 SHA 完成，不修改用户现有代码目录。依赖安装后的实际版本由外部检查入口再次返回，Hive 记录结果。

一个任务分别记录执行代码 SHA、YAML 来源路径/摘要和环境安装来源。默认都引用选定 PR 的同一固定 SHA；需要复用已有安装环境而仅替换测试入口时，明确展示执行代码与安装代码的两个来源。PR 更新后创建新的任务快照，运行中的任务不自动更新。替换 YAML 可以选择 PR 中另一文件，或上传数据配置并归档摘要；YAML 由 PR 中的 runner 解析。能执行 Python/shell 等代码的配置视为代码变更，仍走 PR，不能借配置上传绕过代码来源。

## 容器启动与绑定

已只读确认五台节点都可以读取用户指定的启动脚本。调用约定为：

```bash
bash /mnt/share/c00814587/start-docker-A3.sh <image> <container_name>
```

脚本使用 host 网络、映射全部 16 个 davinci 设备及 /mnt 等目录，已有同名容器时失败。平台生成严格校验的唯一容器名，记录完整容器 ID、启动时间、宿主机 boot ID、镜像 ID 和脚本摘要。当前脚本只有 A3 适配证据；A2/A5 未配置适配启动器时禁止声称环境可创建。

此路径是用户指定的现有外部引导入口，不复制进 Hive，也不改写为 Hive 内置 docker run 配方。首次执行前固定脚本内容摘要并记录来源；摘要变化时不能静默运行新内容，后续启动逻辑变更也按 PR 管理。容器创建必须在宿主机执行，作为明确的引导阶段；安装、测试和业务检查均在容器内执行。

提交时用户只选择 node0、node1 和 server、client 等代称。分配成功后一次性持久化代称到实际节点 ID/IP/卡的绑定，重启恢复沿用绑定，不能按实时列表重新排序。部分卡采用用户已接受的规则隔离，注入分配后的 ASCEND_RT_VISIBLE_DEVICES；不把脚本映射所有设备误认为已完成强制隔离。

host 网络下的新任务端口由脚本管理，旧 API 显式声明的端口仍参与平台互斥。节点代称、服务地址、端口和工作目录通过平台变量提供，卡绑定与身份变量不允许脚本配置覆盖。

## job 行为

React + SVG 按 Archify 流程图设计绘制可编辑依赖关系，仅通过连线配置依赖，并提供明显的删除连线按钮。创建边时拒绝自依赖、重复边和环；后端再次校验。删除被引用的节点或容器代称必须显式修正引用，不能自动换到其他机器。

每个 job 支持多个 Shell、Python 和 YAML 文件，记录类型、路径、名称、顺序、内容摘要和大小限制。上传脚本用于关联并核对 PR 中同内容文件；新增或修改的执行代码先提交 PR，再选择对应版本运行。拒绝路径穿越和空执行入口；上传读取完成后才允许提交。一个 job 按前校验、主入口序列、后确认执行，三个阶段都支持外部文件入口。每个执行步骤是独立进程，不隐式传递上一步的 cd/export 或 Python 内存状态；公共环境在 job 配置中声明。

前校验失败则不执行主脚本。主脚本按序运行，任意非零退出停止后续主脚本。后确认支持成功后执行或始终执行，分别记录结果；后确认成功不能覆盖主脚本失败，后确认失败也不能把任务标为成功。

依赖默认采用 afterok 语义：所有前置 job 成功后就绪；前置失败或取消时下游跳过并记录原因。独立分支可并行，但仍需要环境已就绪、目标卡不冲突、安装锁未占用和并发额度可用。共享同一张卡的计算 job 排队；客户端无卡 job 可显式声明不占 NPU。

job 只在绑定的容器内执行。取消协议不能仅杀掉宿主机 docker exec 客户端，需要在容器内核对并终止 attempt 进程组，确认退出后才允许重用卡。创建、安装、启动各阶段均保存意图与结果；中心重启或 SSH 断线后查询已保存身份，不盲目重跑可能已经启动的命令。

nightly 上述数量包含 2 个 PR-only 精度组（7 个模型）；排除后自动周期矩阵为 114 条、展开后 123 条。weekly 另有 9 个嵌套在 a3-560t 下的 A5 条目，不在当前 workflow 读取路径中，单独标为上游配置异常，不算作有效定时任务。所有已统计入口文件存在、YAML 可解析；这不代表执行通过。

外部入口负责的样例流程为环境核验/安装 → 服务端启动并确认健康 → 客户端性能测试 → 结果确认 → 关闭该任务服务。若 PR 提供独立常驻服务 job，依赖条件需要区分“外部检查确认服务已就绪”和“进程已结束”，不能让客户端等待服务退出才启动。服务最终由任务作用域清理，客户端失败也必须触发清理。Hive 不实现 vLLM 专用健康检查或 aisbench 参数转换。

## 外部执行接口

| 文件类型 | 执行约定 |
|---|---|
| Shell（.sh） | 使用目标环境声明的 shell 解释器，默认 Bash，按文件路径和参数数组启动 |
| Python（.py） | 使用目标容器环境声明的 Python 解释器/虚拟环境，按文件路径和参数数组启动；不使用中心机 Python 执行业务代码 |
| YAML（.yaml / .yml） | 作为配置传给显式指定的 PR 内 Shell/Python 入口或其声明的外部执行器；记录 YAML 与执行器两个来源，不根据扩展名猜测命令 |

YAML 本身不是可执行程序，可以描述安装、测试或校验配置，但具体语义由所选外部执行器负责。每个 YAML 必须关联执行入口和传参位置；执行器缺失时在提交校验阶段报错，不尝试在 Hive 中解释 vllm-ascend 或其他工具的配置格式。允许一个入口引用多个配置文件、多个入口混合文件类型，保留上传时的引用关系。

每个入口声明类型、来源、相对路径、解释器/执行器、参数数组、输入文件、工作目录、环境变量、目标环境、超时和产物路径。Hive 从目标环境解析节点/容器，并提供任务 ID、分配卡、服务地址、工作目录等通用上下文；外部脚本自行解释业务参数。准备前检查目标环境的解释器与引用文件存在，解释器版本由该环境的核验入口记录。实际 argv 和所有输入文件摘要随运行快照记录，日志不泄露平台凭据。宿主机引导步骤使用明确的宿主机解释器，其余业务步骤在对应容器中执行。

进程退出码决定该执行步骤是否成功；精度/性能的通过或失败必须由 PR 中校验入口以退出码或显式结构化结果表达。默认收集 stdout/stderr 和指定的原始产物。需要表格展示时，PR 中的导出脚本可输出通用 JSON：指标名称、数值、单位、标签、判定和原始产物引用。Hive 只验证格式并展示，不解析某个特定业务日志格式或重新计算阈值。业务判定失败不能因导出脚本退出 0 被覆盖；没有业务判定时只显示执行成功及“未提供测试判定”。

预置清单同样由 PR 中的清单文件或枚举脚本提供名称、周期、标签、入口和 YAML 引用。现有上游格式可由 PR 内适配脚本导出通用 JSON，Hive 不内置 nightly/weekly 的专用目录扫描和 YAML 语义解析。预置验证状态属于 Hive 管理数据，未验收的条目不能自行声明为已开放执行。

## 显示与记录

任务列表显示提交人、名称、PR、两个代码 SHA、引用的环境、排队/安装/运行/终态、开始/结束时间和失败原因。环境按逻辑代称分组显示每个节点的实际机器及卡、独立容器名、镜像与依赖版本、解释器、安装状态、复用状态和保留截止时间。无需选择服务端/客户端角色；旧版角色字段仍兼容。同机部署明确显示两个环境绑定到同一节点。

job 显示依赖图、目标环境及实际位置、文件类型、入口与 YAML 引用、解释器/执行器、每阶段状态、服务就绪状态、endpoint、超时、退出码、开始/结束时间和独立日志。日志带任务/job/环境/attempt 身份，续读偏移和上限，前后检查分别记录。不得把不完整日志当作确认执行成功。

结果记录原始产物引用和外部导出入口提供的指标、单位、数据来源、样例数、阈值和判定。性能指标按实际 runner 输出保存吞吐、TTFT、TPOT/延迟等；字段缺失显示未采集。精度用例后续接入时保存任务名、分数及对应判定，不填充假数据。Hive 不实现精度或性能算法、业务结果解析器、模型专属阈值判断。

创建、取消、环境复用/关闭记录归属与审计；安装版本核验以外部 verify 日志为准，不把请求的软件包版本当作实际安装版本。异常恢复保留执行身份与原因。用户只能提交到自己有权使用的环境；管理员操作仍记录实际操作者。

## 多节点环境与执行实例

环境的 `node_aliases` 选择一个或多个申请节点，例如 `["node0", "node1"]`；同一环境代称在每个节点独立创建容器、准备代码和安装依赖。旧版 `node_alias` 单节点输入继续兼容。申请中的每个节点至少由一个环境引用；节点重复、越界或彼此矛盾的单双节点字段在提交时拒绝。

job 引用逻辑环境，可通过 `node_aliases` 选择其中部分节点；未提供时在环境的全部节点执行同一组步骤。每个实例独立占卡、占端口、保存身份、记录阶段日志与结果。依赖使用全部上游实例屏障：上游全部成功或服务全部就绪后，下游各实例才可启动。服务等待其全部消费方实例结束，再确认容器内服务进程退出。取消或通信未知沿用实例级进程核验，未确认退出时保留资源申请。

数据库保留逻辑任务与运行空间配置用于编辑和复用，同时保存独立环境/job 实例执行状态。API 的 `jobs`、`environments` 返回实际实例，携带 `logical_job_id` / `logical_alias` 和 `node_alias`；`logical_jobs`、`logical_environments` 返回分组与聚合状态。复用读取逻辑配置，不把展开后的实例再次展开；已有容器与节点资源映射快照保持原绑定。

| 动态参数 | 含义 |
|---|---|
| `HIVE_NODE0_IP`、`HIVE_NODE1_IP` 等 | 运行空间首次分配后冻结的节点 IP |
| `HIVE_NODES_JSON` | 按节点序号排序的 `[{"node_alias":"node0","host":"...","ip":"..."}]` |
| `HIVE_HOST_IP`、`HIVE_CONTAINER_NAME` | 当前执行实例所在主机与容器 |
| `HIVE_RESOURCE_MAP_JSON` | 当前节点首次绑定时冻结的权重、数据集、镜像和依赖包映射 |
| `${node0.ip}`、`${node1.ip}` | 启动命令/参数中的指定节点 IP |
| `${server.node0.endpoint}`、`${server.node1.endpoint}` | 当前 job 或其直接依赖的指定节点服务地址；同样支持 `.host`、`.port` |
| `${server.endpoint}` | 优先使用与当前 job 同节点的服务实例；只有一个服务实例时使用该实例；其他多实例歧义在提交时拒绝，要求明确节点 |

产物通过 `targets: [{"environment":"server_env","node_alias":"node0"}, ...]` 精确选择环境与节点组合。未提供目标时收集当前 job 实例的容器文件；旧版单独 `environment` 表示该环境的全部节点。每个显式目标在同一逻辑 job 内只归档一次，优先由同节点 job 实例收集，未在该节点运行 job 时交由首个所选节点实例收集。每个目标独立保存容器身份、摘要与下载地址；API 同时返回逻辑环境与节点，不把不同机器的同名路径合并。归档动作发生在负责收集的实例完成步骤后；需要等待其他 job 产出时，须显式声明依赖。

产物绝对路径可包含 `${task_id}` 和 `${job_id}`，例如 `/tmp/hive-results/${task_id}/${job_id}/result.json`。提交时仅在执行实例中解析为实际任务 UUID 和 job 实例 ID；逻辑配置、预置与复用表单保留模板，避免同一容器中的不同任务覆盖结果。业务入口也应将结果写入相同的任务目录；Hive 不移动业务输出。其他模板、解析后重复目标或超长路径在创建申请前拒绝，归档及恢复均使用已解析路径。

展开后最多 128 个环境实例、256 个 job 实例；每个 job 实例最多 16 个产物，继续使用单文件 4 MiB、单次归档合计 16 MiB 上限。超限和重复目标在资源申请创建前拒绝。此能力复用现有 SSH、容器进程协议和 MySQL，不增加调度服务或节点代理。

## 测试先行

用户在补充文件类型和同机独立环境要求后指示开始实现，按前端提交与连线、任务/环境 API、SSH 容器执行三个边界开展 TDD。

实现逐个行为执行“失败测试 → 最小实现 → 通过”。已覆盖普通申请兼容、附任务申请原子幂等、PR 文件固定、同机双环境、job 执行、服务就绪依赖、并行资源互斥、环境复用、失败和取消收尾。模板业务代码仍由外部 PR 提供。

新增测试聚焦编排边界：固定 SHA 后 PR 更新不改变运行内容；只换 YAML 不重装相同环境；更改安装来源不能误复用；使用 PR 中不同入口无需修改 Hive；外部校验失败不能显示测试通过；日志/产物缺失或格式错误不能生成虚假指标。Hive 自身的自动化测试可以包含无业务语义的临时脚本夹具，不复制精度、性能或部署业务代码作为生产预置。

文件入口覆盖 Shell/Python 的解释器选择、混合步骤顺序、YAML 与外部执行器关联、缺失执行器/文件拒绝提交及输入版本固定。部署关系覆盖同机两个不同环境仅申请一次机器、分机代称绑定、客户端零卡与服务端占卡并行、同机端口冲突、服务就绪后启动客户端、服务异常触发收尾、安装输入变化拒绝复用，以及客户端结束不能提前归还服务端资源。

改动前基线：在 Windows 上使用独立 MySQL 测试库运行 `python -m unittest discover -s tests -q`，144 项测试中 140 项通过、4 项 Linux 进程协议测试因平台要求跳过（64.337 秒）。这是现有功能基线，不是新任务编排功能的验收结果。

API 使用独立真实 MySQL 数据库，GitHub 和 SSH 作为外部边界提供可控替身。通过公开接口验证资源互斥、未知结果保留占用、取消、重启不重复执行和权限。浏览器覆盖上传、依赖编辑、普通申请和错误提示。Linux 容器协议另做真实验证，不能以 Windows 上的 mock 通过代替容器后代进程退出证据。

最终样例实机验收还需要用户提供 PR 和可用资源；资源忙时排队，不能清理外部任务腾出设备。其余预置不批量执行。

## 依赖

中心机保留 Python、FastAPI、Uvicorn、PyMySQL、Paramiko、cryptography 和 MySQL；React/Vite 构建后由同一 API 在 18000 端口提供页面。任务调度使用现有 worker 和标准库线程池，不增加 Redis/Celery/Slurm。

Hive 接收通用 JSON 清单和结果，任务 YAML 作为带来源与摘要的输入文件传递给外部 runner；不为解析 vllm-ascend YAML 在中心机增加 PyYAML。业务 YAML 依赖由业务 PR 的容器环境负责。目录导入限制来源、文件大小和结构。DAG 编辑使用 React/SVG，无独立图形框架。最终安装清单随实现更新到 README。

节点继续使用已有 SSH、Bash、Docker、基础进程控制工具和 Ascend 驱动。Git、Python/pip、构建工具、CANN、PyTorch、vLLM、Triton、aisbench 等业务依赖在容器中准备，client 按需安装。软件包链接尚未提供的版本保持不可安装状态，不自动升级或推测下载地址。
