# 硬件身份、CPU 架构与实测算力

2026-09-12，已在当前 5 台 A3 节点完成只读查询，共核验 80 个逻辑设备。

## 型号从哪里来

纳管时记录的 `Atlas 800I A3 / IT22HMDA_4_S` 和 `AC222 / IT22HMDA_2_S` 是两个字段的组合，并非 SoC 型号。页面现只显示服务器型号，隐藏板卡后缀和默认集群名；自定义集群名仍可显示。原始字段保留，机型申请同时兼容原完整名称与简化后的服务器型号：

```bash
# 系统产品名：Atlas 800I A3 或 AC222
cat /sys/class/dmi/id/product_name

# 板卡产品名：输出中的 Product Name
npu-smi info -t board -i 0

# 芯片身份：按设备映射查询每个 NPU ID / Chip ID
npu-smi info -t board -i 0 -c 0
```

这批 A3 的第三条命令返回 `Chip Name: Ascend910`、`NPU Name: 9362` 或 `9382`，组合得到 `Ascend910_9362` 或 `Ascend910_9382`。`Chip Version: V1` 是另一个字段，不能用它替代 SoC version。这种组合方式也见于 [vLLM Ascend 的硬件识别实现](https://github.com/vllm-project/vllm-ascend/blob/main/setup.py)。

| 节点 IP 尾号 | 系统产品 / 板卡产品 | 实机 SoC version | CPU 架构 |
|---|---|---|---|
| 159、197、198 | Atlas 800I A3 / IT22HMDA_4_S | Ascend910_9362 | ARM64（aarch64） |
| 169、174 | AC222 / IT22HMDA_2_S | Ascend910_9382 | x86_64 |

CPU 架构通过 `uname -m` 精确判定，同时保存 `uname -a` 的原始结果供页面详情查看。不能根据主机名、内核版本字符串中的 `aarch64` 或服务器机型推断 CPU 架构。未知架构保留原始 machine 字段，并显示未确认；不会默认为 ARM 或 x86。

## 展示与记录

| 字段 | 来源 / 口径 | 展示与保存 |
|---|---|---|
| 系统产品 | DMI | 节点硬件详情；保留最新值 |
| 板卡产品 | npu-smi board | 保留在后台元数据，不在页面展示 |
| SoC version | 每个逻辑设备的芯片身份 | 集群台账、实时节点头、设备详情；保留逐设备值与节点去重列表 |
| Chip version | npu-smi 的 Chip Version | 硬件详情；逐设备保留最新值 |
| CPU 架构、machine、uname 原文 | `uname -a`、`uname -m` | 集群台账和实时节点摘要显示架构；详情展示原始结果、来源、质量、原因和时间 |
| Ascend-DMI 可用性、路径、版本、原因、检查时间 | 工具路径发现、`ascend-dmi --version` | 节点检测详情；未安装与运行库问题明确标记，版本查询成功不代表算力测试运行库完整 |
| 采集质量、原因、时间、boot_id、查询来源 | 完整性及重启核验 | 硬件详情；保留最新记录 |
| 实测算力 | `ascend-dmi -f -t fp16 -d <Device ID> --et 10 --fmt normal -q`，TFLOPS / 逻辑设备 | 摘要展示全部设备成功后的最小值–最大值；详情展示逐设备 slot、Device ID、TFLOPS、命令和测试时间 |
| 测试状态及恢复原因 | 平台测试执行记录 | 记录申请人、测试 ID、请求/开始/完成时间、状态、boot_id、设备映射、退出失败原因及恢复时间；中断或部分完成不生成完整范围 |
| 理论规格（手动登记） | 管理员提供的 A3 FP16 稠密峰值资料，TFLOPS / 双芯模块 | 仅在详情中保留旧登记入口和值、资料来源、确认时 SoC 和登记时间，与实测数据分开 |

“集群与规格”表头的问号在鼠标悬浮或键盘聚焦时显示每项指标的查询方式，包括纳管填写的代际/集群、DMI 机型、SoC、显存、CPU 架构及实测算力。每卡显存来自 `npu-smi info` 的 HBM / Memory-Usage 总量，从 MiB 换算到 GiB；这里的“卡”指平台分配的逻辑设备。

## 手动测试及申请冲突判断

管理员在“集群管理 → 查看检测结果 → 运行 FP16 算力测试”提交。此操作有实际计算负载，不由定时采样、普通重新检测或打开页面自动触发。[厂商说明](https://www.hiascend.com/doc_center/source/zh/mindx-dl/500/toolbox/toolboxug/toolboxug_0016.html) 中的 `TFLOPS@FP16` 是矩阵计算所得的实测值；`--et 10` 是执行次数系数，不是测试十秒，结果受环境与频率等因素影响。`-q` 用于已由管理员触发的非交互执行。

1. **提交时**：只接受管理员和 Ascend 节点；拒绝重复测试。节点及全部逻辑设备必须采样新鲜、健康且采集完整，无平台所有权申请、无实际 NPU 进程、AI Core 为 0、显存在已确认的空闲基线内，且工具已检测可用。任一设备未满足即拒绝整机测试。
2. **占用整机**：在与资源申请相同的节点数据库锁内记录测试并设置维护状态，阻止机器申请和后续任务分配。记录原维护状态，测试活动期间禁止提前解除维护。不会清理用户进程来腾出机器。
3. **执行前复验**：独立后台执行器逐设备测试，每次执行前重新采样整机并复验空闲、boot_id 和完整设备映射。命令使用逻辑 Device ID，不能把 NPU ID 或 Chip ID 当成 Device ID。单设备远端命令有 60 秒超时及强制终止宽限。
4. **完成与释放**：全部设备测试成功、结束后再次确认整机空闲，才给出完整实测范围并恢复原维护状态；原先已处于维护的节点仍保持维护。测得的值不会乘二或替换成 560 / 752 TFLOPS。
5. **失败与中断**：缺少工具、运行库、返回错误、设备不空闲、映射变化或无法解析均记录原因，不填零、不自动重试压测。worker 中断后等待远端命令超时上界，再重新采样核验；无法确认整机空闲时保持恢复状态并定期复核。此时不释放整机供新申请使用。

节点重启会使旧的显存空闲基线失效。若测试期间重启，管理员需在确认各卡空闲后重新确认基线，恢复检查才会还原原维护状态。失败/成功详情可展开查看最近一次命令输出及 Device ID；输出保留最多 4096 字符，并去除当前节点密码。

未经测试显示“未测试”，工具缺失显示“工具未安装”。重启后的历史成功结果标记待复测。旧的手动理论规格继续以原口径保留在详情：没有证据将 `9362/9382` 映射到 `560/752`，不做猜测。

仅在当前 A3 SoC 采集完整且 boot_id 一致时接受双芯模块算力登记。后续 SoC 不同或采集不完整时，已登记数值显示“待复核”。A2/A5 的 SoC 识别接口已预留；当前没有实机验证，不沿用 A3 的双芯算力口径。

## 模块与依赖

`hardware_profile.py` 处理低频身份采集，由 Ascend 适配器通过 `describe_hardware` 暴露；`host_system.py` 独立解析通用 Linux 主机架构；`ascend_dmi.py` 复用工具查找和环境准备；`compute_benchmark.py` 管理手动测试生命周期。纳管、手动重新检测、重启触发检测共用硬件采集入口，不加入每 15 秒的实时采样。每批 SoC 查询核验 boot_id 和返回的设备身份；缺失信息不影响实时指标采集。算力任务使用独立执行线程和 SSH 连接池。

最新记录保存在 MySQL 已有的 `nodes.metadata.hardware_profile` / `compute_benchmark` / `compute_spec`，并写入测试请求和结束审计，不新增数据库表、第三方队列或时序聚合。每次手动测试覆盖节点最新测试记录；实测算力目前是展示属性，尚未加入申请筛选条件。维护状态与既有设备空闲判断复用于申请排他，普通机器申请的半小时保护和回收规则不变。

中心无新增依赖，复用 Python/SSH/MySQL；节点的架构和 SoC 查询使用 Bash、coreutils（uname、cat、timeout）、npu-smi 与 DMI sysfs。**仅算力实测**额外依赖已安装的 Ascend-DMI 及兼容的 CANN 运行库；工具可选，不是裸机纳管的强制依赖，也不统计 CANN 版本。工具路径及部署见 [README](../README.md#61-节点需要的工具)。平台不安装/升级驱动、CANN、ToolBox 或节点常驻组件。

## 验证

2026-09-12 的真实只读检查确认：三台 ARM64、两台 x86_64；`.197` 的 Ascend-DMI 为 7.3.T，`.198` 为 26.0.1.1；其余三台在受支持路径未检测到工具。两台有工具的节点存在外部 NPU 进程，因此本次没有在它们上执行压测或写入实测数字。测试覆盖解析、架构识别、缺失工具、测试权限、申请排他、失败与中断恢复；数据库测试使用独立临时 MySQL 库，SSH 算力执行使用受控回包。真实硬件执行成功仍需在工具完整且整机空闲时验收。
