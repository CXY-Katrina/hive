## 互联与共享盘

纳管默认每台选一个 NPU，验证所有节点方向：5 台共 20 条方向，NPU HCCS ping、TLS 一致性和管理 SSH TCP 均通过；每节点显示“抽检 8 / 8、4 个对端”。这是节点初筛，不保证任意卡组合或任意业务 TCP 端口可用。

实际申请勾选互联时，仍对最终选中卡集合执行全部跨节点有向组合检查。适配器提供可选批量接口，复用地址/TLS 查询并分批执行有界 ping；其他硬件适配器可继续使用原来的单对接口。大规模整机多机申请的完整检查仍可能需要较长时间。

纳管初期尝试全组合 5,120 条探测，因实机耗时与轻量目标不符而停止；未完成的组合没有记为通过。检测没有修改防火墙、TLS、路由或驱动配置。

`/mnt/share`、`/mnt/weight` 均通过 5 台节点之间的实际随机文件写入与交叉读取。不同机器使用 hostname/IP 挂载别名；仅在实际读写验证成功后统一共享组 ID，保留各自真实挂载源。探测文件已清理。同名本地目录或不同内容的挂载不能借此获得“已验证”状态。

检查方法参考用户指定的 [toolkit 互联指导](https://github.com/xuchi-0808/blue-server-toolkit/blob/main/docs/npu-roce-connectivity.md) 和 [A3 编号说明](https://github.com/xuchi-0808/blue-server-toolkit/blob/main/docs/a3-chip-numbering.md)。裸机没有增加 CANN/HCCL/torch 依赖。
